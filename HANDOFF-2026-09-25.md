## Deployment model (important, non-obvious)

The `/opt` tree is **not** git-pulled: HEAD there is stale at `c059762`; code is rsynced
from the Windows checkout. As of 2026-09-20 ~21:45 -03 it is byte-identical to master
`2f6adda`+docs (`5e9183d`). Services load code only at start. Deploy recipe (needs
authorization): stop `cbrs-worker`, stop `cbrs-browser-owner`, `rsync -rlt --no-perms`
from `/mnt/v/scrapper/scrapper-portal-conservador/` excluding `.git .venv .env .cbrs outputs
__pycache__ /tmp build *.egg-info`, `chown -R cbrs:cbrs`, start owner, wait ~8 s, start
worker. Sessions survive (cookies in per-route profiles).

Practical WSL usage from Git Bash: write scripts with the Write tool and run
`wsl.exe -d Ubuntu-24.04 -- bash -s < script.sh` (passing `/mnt/c` paths as arguments gets
mangled; heredocs re-encode non-ASCII). No `.venv/bin/cbrs` in the runtime: use
`.venv/bin/python -m cbrs ...`. Run as the service user with
`runuser -u cbrs -- env DISPLAY=:99 HOME=/opt/scrapper-portal-conservador/.cbrs/runtime
.venv/bin/python deploy/run_with_env.py .env -- <cmd>`.
