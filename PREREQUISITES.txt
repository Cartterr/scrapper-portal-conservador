PRERREQUISITOS DE INSTALACION CBRS - WINDOWS NATIVO
===================================================

Ruta soportada
--------------

- Windows 11 x64 con el usuario operador autorizado iniciado.
- PowerShell elevado y winget disponibles.
- No usar WSL, Docker, Xvfb, hipervisores ni maquinas virtuales.
- El instalador puede instalar nativamente Python 3.14, Google Chrome y restic.
- G:\CBRS se usa para estado, perfiles, logs y PDFs.
- E:\CBRS-backup\restic debe estar en un volumen fisico separado para backup.

Cuentas y acceso
----------------

- Tres cuentas CBRS nominales y expresamente autorizadas.
- Una identidad CBRS, un perfil Chrome y un puerto proxy exclusivo por cuenta.
- Chrome normal instalado es el navegador productivo probado; Playwright lo
  controla con perfiles persistentes y CBRS_HEADLESS=1 por defecto.
- GoLogin y Dolphin Anty son herramientas diagnosticas opcionales. No son
  requisitos, no son instalados y no deben poseer los perfiles del worker.

DataImpulse Mobile
------------------

- Plan Mobile Proxy con trafico disponible.
- Credenciales proxy del plan movil; no usar email/password del dashboard ni
  credenciales de otro plan.
- Host gw.dataimpulse.com, protocolo HTTP, pais cl y sessttl.120.
- Tres puertos sticky iniciales distintos: 10000, 10001 y 10002.
- Rango de recuperacion permitido: 10000-20000.
- DATAIMPULSE_ASN queda vacio hasta validar un ASN movil chileno concreto; su
  uso duplica el trafico.
- Residential queda soportado solo como fallback explicito.

CAPTCHA
-------

- Configurar una clave valida de CapSolver o 2Captcha solo si se habilitara el
  solver correspondiente.
- Las claves de solver no son credenciales proxy.
- Mantener limites diarios, timeouts y circuit breakers del template.

Secretos
--------

- Completar valores reales solo en C:\ProgramData\CBRS\cbrs.env.
- Guardar el password de restic en C:\ProgramData\CBRS\restic-password.
- Ambos archivos deben tener herencia ACL removida y acceso limitado al usuario
  operador, Administrators y SYSTEM.
- No guardar credenciales, URLs proxy completas, cookies, tokens, IPs crudas ni
  respuestas sensibles en Git, logs, SQLite, capturas o documentacion.

Instalacion
-----------

Desde PowerShell elevado en la raiz:

  .\deploy\windows\Install-CbrsNative.ps1

Tambien se puede usar INSTALL-CBRS.bat. La opcion --plan solo muestra el plan.
Install-CbrsE2E.ps1 es un alias compatible que delega al instalador nativo.
El instalador registra worker, dashboard, watchdog y backup, pero los deja
deshabilitados y no inicia Chrome ni trafico CBRS.

Configuracion inicial
---------------------

1. Completar las tres credenciales CBRS mediante:

   .\deploy\windows\Set-CbrsNativeAccountCredentials.ps1

2. Normalizar env y pool al plan movil con el worker detenido:

   .\deploy\windows\Set-CbrsDataImpulseNetwork.ps1 -Network mobile

3. Si se importan URLs proxy heredadas, usar:

   .\deploy\windows\Set-CbrsDataImpulseProxySessions.ps1 -Network mobile

4. Ejecutar readiness sin iniciar navegador:

   .\.venv\Scripts\python.exe -m cbrs readiness --target windows `
     --env-file C:\ProgramData\CBRS\cbrs.env `
     --config G:\CBRS\account-pool.json

5. Solo despues de aprobar los gates, iniciar explicitamente:

   .\deploy\windows\Start-CbrsNative.ps1 -AcknowledgeAuthorizedLiveTraffic

Gates de aceptacion
-------------------

- Chrome, Python, dependencias, restic y cuatro Scheduled Tasks presentes.
- Tres perfiles distintos, tres puertos sticky distintos y tres baselines CL.
- Un unico lease vigente del worker.
- Dashboard limitado a 127.0.0.1.
- 3/3 contextos Chrome vivos y 3/3 estados authenticated_form.
- Una consulta autorizada produce un PDF valido y la sesion sigue autenticada.
- Rotar una cuenta no cambia los otros dos procesos Chrome.
- Backup y restauracion de prueba verificados.
